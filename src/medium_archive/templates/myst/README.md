# A MyST site

Generated by `medium-archive myst` from an archived Medium publication:
posts as MyST Markdown with their images, and `myst.yml` with the table
of contents.

## Build

```sh
myst start                    # serve, rebuilding on change
myst build --html             # render into _build/
```

Requires `mystmd` (`npm install -g mystmd` or `pip install mystmd`),
which fetches its site template on the first build.

## What to edit

| file | contents |
|------|----------|
| `myst.yml` | title, description, URL, table of contents, plugins |
| `index.md` | landing page: blurb and cover gallery |
| `archive.md` | chronological post list by year |
| `posts/<date>-<slug>/<page>.md` | posts, with their images beside them |
| `listing-covers.mjs` | plugin giving the gallery local cover thumbnails |

Set `site.options.url` in `myst.yml` to the real domain.

## Write a post

```
posts/2026-01-31-a-new-post/
  a-new-post.md
  images/diagram.png
```

```markdown
---
title: A new post
date: 2026-01-31
authors:
  - name: Ada Lovelace
tags:
  - jupyter
description: Excerpt and meta description
thumbnail: images/cover.jpg
---

The body, as MyST Markdown.

![a diagram](images/diagram.png)
```

- The file name is the page URL, capped by mystmd at 50 characters.
- `tags` are display names; there are no tag pages.
- `thumbnail:` is the gallery cover.
- Add the page to `myst.yml`'s table of contents to link it.

## Regenerating

`medium-archive myst` overwrites the files it generates and leaves
others alone. While the site is still generated, make corrections in
the archive (`site/site.toml`, `archive/tags.json`, the post). Once this
directory is its own repository (`medium-archive myst --out DIR`;
`--clean` removes pages the archive no longer has, keeping `.git/` and
ignored files), edit the files here.
